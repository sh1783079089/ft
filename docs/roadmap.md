# 发布路线图

本文档描述项目的发布节奏与各版本目标。版本号遵循[语义化版本](https://semver.org/lang/zh-CN/)（SemVer），`v*` 形式的标签会触发 GitHub Actions 自动构建并发布可执行文件。

## 发布策略

- 版本号：`MAJOR.MINOR.PATCH`，预发布与首个开源版本从 `0.x` 起步。
- 标签：推送形如 `v0.1.0` 的标签后，`.github/workflows/release.yml` 自动构建 `file_tracker.exe` 并创建 GitHub Release。
- 持续集成：每次推送/PR 触发 `ci.yml`，执行 gcc 与 CMake 构建、clang-format 格式检查。
- 当前平台：**仅 Windows**（依赖 `conio.h`、`direct.h`、`windows.h`）。

## v0.1.0（当前版本）

**目标**：完成首个开源版本，具备完整的单文件版本管理能力。

已实现：

- 控制台菜单交互，无需命令行参数。
- 单文件仓库初始化、提交、历史查看、版本恢复。
- 自实现 SHA-256 内容摘要；blob 按哈希去重并维护引用计数。
- 提交历史使用双向链表（`next` 全局时间链、`prev` 分支父链）。
- 分支管理（创建、切换、删除）与标签管理。
- 文件监控，内容真实变化时自动提交。
- ASCII 提交图可视化。

发布物：`file_tracker.exe`（Windows）。

已知限制（将在后续版本处理）：

- 无自动化测试。
- 仅支持 Windows，未提供 CLI。
- 元数据未采用原子写入/文件锁，存在一致性风险。
- 提交入口未拦截超过 `MAX_COMMITS` 的新提交。

## v0.2.0 — 测试与质量

**目标**：建立自动化质量保障。

- 引入 `CTest` 单元测试，覆盖 SHA-256 摘要、路径解析、blob 去重、存储往返与加载校验。
- CI 增加测试任务，构建后运行 `ctest`。
- 元数据采用原子写入（写临时文件后重命名）。
- 提交入口拦截超过 `MAX_COMMITS` 的提交并给出提示。

## v0.3.0 — 跨平台

**目标**：摆脱 Windows 专属 API，支持 Linux / macOS。

- 抽出平台适配层，封装 `conio.h` / `direct.h` / `windows.h` 等差异。
- 终端交互、目录创建、文件时间与休眠改为可移植实现。
- CI 构建矩阵扩展为 `windows-latest` / `ubuntu-latest` / `macos-latest`。

## v0.4.0 — 命令行接口（CLI）

**目标**：在保留交互菜单的同时提供脚本友好的命令行。

- 新增子命令，例如 `init`、`commit`、`log`、`restore`、`branch`、`tag`、`graph`、`watch`。
- 统一参数解析、退出码与输出格式。
- 交互菜单作为无参数时的默认入口保留。

## v1.0.0 — 开源可用

**目标**：达到可稳定用于日常、可被外部贡献者使用的程度。验收标准：

- 自动化测试齐全且 CI 全绿。
- 跨平台可编译运行（Windows / Linux / macOS）。
- 提供 CLI 与交互菜单两种使用方式。
- 文档完善：安装、用法、构建、贡献指南与变更日志齐备。
- 存储格式稳定并保证向后兼容。
